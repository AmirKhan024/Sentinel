# Raw data contract — Chicago Food Inspections

This describes what a file in `data/raw/food_inspections/` contains and what
guarantees it carries. It is the contract every downstream component may rely
on.

---

## Identity

| | |
|---|---|
| Source | Chicago Data Portal (Socrata SODA 2.1) |
| Dataset | Food Inspections |
| Dataset ID | `4ijn-s7e5` |
| Endpoint | `https://data.cityofchicago.org/resource/4ijn-s7e5.json` |
| Layer | `raw` — unmodified apart from JSON→columnar encoding |
| Format | Apache Parquet, zstd compression |
| Produced by | `sentinel ingest` (`src/sentinel/ingest/food_inspections.py`) |

## File naming

```text
data/raw/food_inspections/
  food_inspections_<YYYYMMDD>T<HHMMSS>Z.parquet     the data
  manifest_food_inspections_<YYYYMMDD>T<HHMMSS>Z.json   its provenance record
```

The timestamp is the UTC time the ingestion **started**. Every run creates a new
pair; nothing is ever overwritten. The raw layer is append-only.

Parquet files are gitignored. Manifests are committed.

---

## The central guarantee: every column is a string

**All columns are Parquet `BYTE_ARRAY (UTF8)` — Polars `Utf8`, DuckDB
`VARCHAR`.** No exceptions, including columns the source declares as `number`
or `calendar_date`.

This is not an oversight. The Socrata API returns every value as a JSON string
(see [socrata_findings.md §5](../api/socrata_findings.md)), and the raw layer
preserves exactly what the API returned. Two reasons:

1. **Fidelity.** Casting `"41.86568627741837"` to a float, or an unparseable
   date to null, destroys evidence. If a value is malformed, that fact must
   survive into the raw layer where it can be detected, not be silently
   converted into a null that looks like missing data.
2. **Separation of concerns.** Deciding that `license_ = "0"` means "no
   license" or that `results = "Out of Business"` is not an inspection outcome
   are *modelling* decisions. They belong in a component where they can be
   named, tested and documented — not hidden inside a download script.

**Downstream components must cast explicitly**, and are expected to handle and
report cast failures rather than coercing them to null.

## Columns

22 columns: 17 source columns and 5 Socrata-generated spatial annotations.

| Column | Socrata declared type | Raw Parquet type | Notes |
|---|---|---|---|
| `inspection_id` | number | Utf8 | Unique per inspection; used as the pagination sort key |
| `dba_name` | text | Utf8 | "Doing business as" name |
| `aka_name` | text | Utf8 | Alternate/common name; may differ from `dba_name` |
| `license_` | number | Utf8 | City licence number. Trailing underscore is the actual field name |
| `facility_type` | text | Utf8 | Free-text-ish; observed blanks |
| `risk` | text | Utf8 | e.g. `Risk 1 (High)`. Assigned by the city, not by Sentinel |
| `address` | text | Utf8 | Street address as recorded |
| `city` | text | Utf8 | Observed values are not exclusively `CHICAGO` |
| `state` | text | Utf8 | Observed `IL` |
| `zip` | number | Utf8 | Postal code as a string; leading zeros would be preserved |
| `inspection_date` | calendar_date / floating_timestamp | Utf8 | ISO-8601 with a zero time component, e.g. `2010-01-05T00:00:00.000` |
| `inspection_type` | text | Utf8 | e.g. `Canvass`, `Complaint`, `License` |
| `results` | text | Utf8 | e.g. `Pass`, `Fail`, `Pass w/ Conditions`, `Out of Business` |
| `violations` | text | Utf8 | Long free text; multiple violations separated by ` \| `, each with a numbered code and a `- Comments:` section |
| `latitude` | number | Utf8 | WGS84, as a string. May be null |
| `longitude` | number | Utf8 | WGS84, as a string. May be null |
| `location` | location | Utf8 | **Nested object, re-serialized to compact JSON.** Contains `latitude`, `longitude`, and a `human_address` field which is itself a JSON string (observed empty) |
| `:@computed_region_awaf_s7ux` | number | Utf8 | Historical Wards 2003-2015 |
| `:@computed_region_6mkv_f3dw` | number | Utf8 | Zip Codes |
| `:@computed_region_vrxf_vc4k` | number | Utf8 | Community Areas |
| `:@computed_region_bdys_3d7i` | number | Utf8 | Census Tracts |
| `:@computed_region_43wa_7qmu` | number | Utf8 | Wards |

The `:@computed_region_*` columns are generated by Socrata by joining the row's
coordinates against boundary layers. They are **not** city-supplied source
data, and they are absent when latitude/longitude are missing. They are
captured because they are cheap geographic keys, but any component that depends
on them should treat them as derived, not authoritative.

### Transformations applied

Exactly three, and no others:

1. JSON records → Parquet columns.
2. The nested `location` object → its compact JSON string
   (`json.dumps(..., sort_keys=True, separators=(",", ":"))`).
3. Keys absent from a record → null in that column.

Explicitly **not** applied: type casting, trimming, case normalisation, null
harmonisation (`""` vs `null` vs `"N/A"`), deduplication, filtering, renaming,
or column dropping.

## Manifest

Each Parquet file has a JSON sidecar recording:

| Field | Purpose |
|---|---|
| `source`, `source_url`, `dataset_id`, `dataset_name` | what was fetched |
| `retrieved_at` | UTC timestamp, ingestion start |
| `code_version` | `sentinel.__version__` that produced it |
| `mode`, `row_limit` | `dev` (capped) or `full` |
| `page_size`, `pages_fetched` | pagination shape |
| `order_column` | the sort key used for stable paging |
| `request_params` | the exact `$limit`/`$offset`/`$order`/`$select` for every page |
| `row_count`, `column_names` | what came out |
| `socrata_field_names`, `socrata_field_types` | source-declared schema from the response headers |
| `parquet_schema` | column → Polars dtype, all `String` |
| `output_path`, `output_bytes` | where it went and how big |
| `sha256` | checksum of the Parquet file |

The checksum answers "is this file still the one the manifest describes?". The
`request_params` list makes the run replayable: the exact request sequence is
recorded rather than re-derived.

## Known caveats

These are properties of the data or the extraction, not bugs. Later components
must handle them.

1. **A development pull is not a random sample.** Pagination is ordered by
   `inspection_id`, and inspection IDs correlate with time. A `--limit 5000`
   pull therefore returns the **oldest** 5,000 inspections (observed:
   2010-01-04 to 2011-05-09), not a representative cross-section. Never use a
   dev extract to estimate distributions, and never train on one.
2. **No deduplication.** The source may contain multiple rows for the same
   establishment and date. Untouched here.
3. **`license_` is not an entity key.** It is not guaranteed unique, stable, or
   present. Resolving establishments is Component 2's entire job.
4. **Blank vs null are different.** The source uses empty strings in some
   places (observed in `facility_type`) and true nulls in others. Both survive
   verbatim; neither is harmonised.
5. **`violations` is unstructured.** Numbered codes and comments in one long
   string, with ` | ` between entries. Parsing it is a later component's job.
6. **Geocoding may be missing.** `latitude`/`longitude`/`location` can be null,
   in which case the `:@computed_region_*` columns are also absent.
7. **The dataset is live.** Two ingestions on different days will differ. This
   is why every file is timestamped and every run manifested.
8. **`inspection_date` has no timezone.** It is a floating date with a zero
   time component. Do not assume UTC.
